## 概述

本文档描述智能客服系统的备份与恢复策略，确保数据安全和业务连续性。

## 备份策略

### 备份类型

1. **全量备份**：备份整个数据库
2. **增量备份**：备份自上次备份以来的变更（使用 WAL 归档）
3. **文件备份**：备份 MinIO 中的文件

### 备份频率

| 备份类型 | 频率 | 保留时间 |
|---------|------|---------|
| 全量备份 | 每天凌晨 2:00 | 7 天 |
| 增量备份 | 每小时 | 24 小时 |
| 文件备份 | 每天凌晨 3:00 | 7 天 |

### 备份存储

- **本地存储**：`./backups/` 目录
- **远程存储**：建议使用云存储（AWS S3、阿里云 OSS 等）
- **异地备份**：建议至少一份备份存储在异地

### 备份验证

- 每周验证一次备份完整性
- 每月进行一次恢复演练

## 恢复策略

### 恢复场景

1. **数据误删除**：恢复单个表或记录
2. **数据库损坏**：恢复整个数据库
3. **系统迁移**：将数据迁移到新服务器

### 恢复流程

1. **评估损失**：确定需要恢复的数据范围
2. **选择备份**：选择最近的可用备份
3. **停止服务**：停止 API 服务
4. **恢复数据**：执行恢复操作
5. **验证数据**：检查数据完整性
6. **启动服务**：启动 API 服务
7. **监控运行**：观察系统运行状态

### 恢复时间目标 (RTO)

- **数据库恢复**：< 30 分钟
- **文件恢复**：< 1 小时
- **系统完全恢复**：< 2 小时

### 恢复点目标 (RPO)

- **数据丢失**：< 1 小时（基于每小时增量备份）

## 备份脚本

### 数据库备份

```bash
#!/bin/bash

# 全量备份
./scripts/backup/backup.sh

# 增量备份（需要配置 WAL 归档）
# 参考 PostgreSQL WAL 归档配置
```

### 文件备份

```bash
#!/bin/bash

# MinIO 数据备份
mc mirror minio/customer-service ./backup/minio/
```

### 自动化备份

使用 cron 定时任务：

```bash
# 编辑 crontab
crontab -e

# 添加备份任务
# 每天凌晨 2:00 执行全量备份
0 2 * * * /path/to/scripts/backup/backup.sh

# 每天凌晨 3:00 执行文件备份
0 3 * * * /path/to/scripts/backup/backup-files.sh
```

## 恢复脚本

### 数据库恢复

```bash
# 恢复指定备份
./scripts/backup/restore.sh ./backups/backup_20260612_020000.sql.gz
```

### 文件恢复

```bash
# 恢复 MinIO 数据
mc mirror ./backup/minio/ minio/customer-service
```

## 监控与告警

### 备份监控

- 监控备份任务执行状态
- 监控备份文件大小变化
- 监控备份存储空间使用情况

### 告警规则

- 备份任务失败时立即告警
- 备份文件异常变小时告警
- 存储空间不足时告警

### 告警方式

- 邮件通知
- 短信通知
- Webhook 通知

## 灾难恢复

### 灾难场景

1. **服务器硬件故障**：服务器无法启动
2. **数据中心故障**：整个数据中心不可用
3. **人为误操作**：误删除重要数据
4. **安全攻击**：勒索软件等攻击

### 灾难恢复计划

1. **预防措施**
   - 定期备份验证
   - 异地备份
   - 安全防护

2. **应急响应**
   - 评估损失
   - 启动灾难恢复流程
   - 通知相关人员

3. **恢复步骤**
   - 准备新环境
   - 恢复数据
   - 验证系统
   - 恢复服务

4. **事后处理**
   - 分析原因
   - 改进措施
   - 更新文档

### 灾难恢复演练

- 每季度进行一次灾难恢复演练
- 记录演练结果
- 改进恢复流程

## 备份配置示例

### PostgreSQL WAL 归档配置

```sql
-- postgresql.conf
wal_level = replica
archive_mode = on
archive_command = 'cp %p /path/to/archive/%f'
```

### MinIO 备份配置

```yaml
# mc alias 配置
mc alias set backup https://backup-server access-key secret-key
```

## 备份工具

### 数据库备份工具

- `pg_dump`：PostgreSQL 官方备份工具
- `pg_basebackup`：物理备份工具
- `pgBackRest`：高级备份工具

### 文件备份工具

- `mc`：MinIO 客户端
- `rclone`：多云存储同步工具
- `rsync`：文件同步工具

## 备份最佳实践

1. **定期验证**：定期验证备份的可恢复性
2. **多地存储**：至少存储在两个不同位置
3. **加密备份**：对敏感数据备份进行加密
4. **监控告警**：监控备份任务执行状态
5. **文档记录**：记录备份和恢复流程
6. **定期演练**：定期进行恢复演练
7. **版本控制**：保留多个版本的备份
8. **自动化**：尽量自动化备份和恢复流程
